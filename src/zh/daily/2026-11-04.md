### 一、原生游戏移植可行性调研（Telegram 会话，20:20 – 23:08+，591 条消息）

起点是用户的一个问题：**「你觉得现在 iOS 的能力能跑这个游戏吗」**（指 2009 年 Radical 的《虐杀原型 / Prototype》）。整场会话从"能不能跑"一路推进到"怎么做原生移植"，中间经过多轮技术路线纠偏。

**调研第一阶段：iOS 能不能跑（20:20 – 21:00）**

- 查证游戏本体门槛：Prototype PC 版要求 Core 2 Duo 2.6GHz / 2GB 内存 / DirectX 9.0c，PS3 版内部分辨率仅 1152x640，比 GTA V 轻得多
- 给出三条路线并逐一核实：
  - **A. PC 版 + Madeira**（Wine ARM64EC + FEX-Emu + DXMT）—— Prototype PC 版仍在 Steam（app/10150，$6 左右），但 Madeira 官方只验证过 Thumper、ULTRAKILL，2009 年 DX9 老游戏属未知坑
  - **B. PS3 版 + RPCS3 iOS 移植** —— RPCS3 上 Prototype 状态为 Playable（论坛实测 Ryzen 5600X + RTX 4060 室外 30 FPS 可通关）；iOS 侧已有 iPad Pro M4 跑 GTA V / Infamous / God of War 3 的实测
  - **C. PS4 云串流（PS Plus Premium）** —— 零折腾但依赖网络
- 结论：iOS 26 收紧 JIT 后模拟器路线门槛大幅抬高

**调研第二阶段：recomp 生态与现成项目盘点（21:00 – 21:09）**

- 摸清 recomp 生态规模：recomp.fyi 统计 Xbox 360 有 288 个 recomp 项目（PS1 281、N64 135、PS2 56、PS3 32），仅 9 月就新建 174 个 ReXGlue 项目
- 盘点出 Prototype 的三个现成移植项目：
  - `fungalspores/prototype-switch` —— Xbox 360 → Switch，ReXGlue + Vulkan，**Playable**，游戏内 22-30 FPS，Prototype 1&2 都做了
  - `VinTeRuS/proto-re` —— PC 版 x86 → C 静态重编译 → arm64 Android，Pixel 6 上 38-46 FPS，但作者 v0.2.0 后弃坑
  - `petrishevgeorgii-debug/prototype-pc-slop` —— PS4 版 → Windows native，Playable 60 FPS，PCGamingWiki 收录
- 查到 iOS 落地的现成模板 `bep1s69/nfsmw-ios`（NFS MW → iOS，ReXGlue + MoltenVK），以及 `Theft4` 的审计文档（记录了 16KB page vs `0x1000` 偏移、AppKit 不能进 iOS SDK、shader 需转 SPIR-V 等坑）
- 结论：codegen 是全自动的，工作量在 runtime（内核调用 / 文件系统 / 音频 / 输入 / GPU 后端）

**调研第三阶段：REA 框架定位修正（21:09 – 21:21）**

用户指出说的是 `morluto/rea` 这个 MCP 逆向框架。通读其 native / cli / contracts 三份文档后修正了此前的乐观判断：

- REA（MIT，npm `rea-agents` v6.8.0）**官方支持列表里就有 Hermes**（`rea setup --client hermes` 直接写 `~/.hermes/config.yaml`）
- **REA 没有 codegen** —— 在 native/cli/contracts 里 grep `recompil` / `lift` / `codegen` / `emit`，零命中。它输出伪代码、汇编、调用图、证据，**不生成可编译的 C/C++**
- 所以 REA 的定位是"把『读懂游戏』从几周压到几天"，而不是"生成能跑的原生代码"
- REA 的三个官方 showcase 正好印证这个方法论：DX-Ball（3205 个 x86 用例全过、63 个编译字节完全复现）、TH04（PC-98 16-bit 角度计算）、Notion（Electron 剪贴板桥）
- **本机三个拦路虎**：Node v22.22.2 差 REA 要求的小版本（需 ^22.23.4）、没有 Java/Ghidra、没有 Hopper/IDA/Kuna（只有 objdump）
- 额外发现：Ghidra 有 GameCube DOL lane（PowerPC 大端），但**没有 PS3/XEX lane** → PS3 版别想走 REA 直接分析，走 360 版更顺

**调研第四阶段：关键技术纠偏（21:21 – 21:48）**

用户连续提出三个质疑，全部验证后确认质疑成立，之前的结论被推翻：

1. **「你这个能是虐杀原型的移植包吗？才 60m 不到，作为一个 3A 游戏的体量是不可能的」**
   → 拆开 v0.2.0 APK 逐个 so 核对：`libmain.so` 68.0 MB、`libmain_v80.so` 68.0 MB、`libvulkan_freedreno.so` 14.2 MB、`libdxvk_d3d9.so` 3.2 MB、`libSDL2.so` 1.4 MB、`libFAudio.so` 0.25 MB —— **确实一个游戏资源都没有**
   → 但结论是反的：Steam depot 7.87 GiB 里 **7.75 GiB 全是 11 个 `.rcf` 归档**（美术/音频/关卡），51MB = 引擎 + 运行时，游戏数据另走 Steam，这与 Skate 3 recomp / NFSMW recomp 的做法一致
   → 顺手做了符号表对撞验证：`.so` 里 126,974 个 `f_<va>` 符号，`re/functions.csv` 匹配 105,037（82.72%），`extra_functions.txt` 覆盖 20,358（100%），非 thunk 条目 73,046 全覆盖；样例 `f_7c001005 → proto::fightitems::motion::SetVehicleSolverEnabledTrack` 确认是真实引擎符号；`.text` 段 50.87 MB = 1330 万条 AArch64 指令
   → **更正此前口误**：先前说"73595 个函数"，实际是 **126,974 个**（105,037 + 20,358 + thunk）

2. **「我不是要一个 rosetta 一样的砖译器，我要的是能够原生支持安卓的游戏应用。就像杀戮尖塔之类的移植游戏一样」**
   → 梳理技术谱系三类：重实现/源码移植（OpenMW、DevilutionX、**杀戮尖塔**= libGDX Java）／反编译 decomp（SM64、Ocarina）／静态重编译 recomp（proto-re、Unleashed Recompiled）
   → 实证 proto-re 属于第二类：`.so` 里 514 个非 `f_` 函数全是 Win32 兼容层（`kernel32.cpp` 自实现 CreateFile/VirtualAlloc、`msvcr80.cpp` 自实现 CRT、`advapi32.cpp` 模拟注册表、`user32.cpp` 窗口消息循环、`imports.cpp` PE 导入表解析、`loader.cpp` 自写 PE 加载器），还有 `"hklm\software\activision\prototype"` 模拟注册表和 `"\prototypef.exe"` 模拟 EXE
   → 结论：proto-re 是 **AOT 预编译版砖译器**，不是原生应用；工作量差一个数量级

3. **「现在不是有 rea 工具了吗？与其反编译，不如逆向+重实现」**
   → 用实测数据重算 `re/functions.csv`：总 105,037 条 → thunk 31,442（5 字节跳转桩）／真实函数 73,595，其中 **RTTI 样板 33,550（45.6%）**、未命名 34,068（46.3%，5.07 MB）、已命名仅 5,977（8.1%，0.58 MB）
   → 关键量级差异：反编译要**字节等价**，重实现只需**行为等价**；45.6% 的 RTTI 样板可以重新设计类结构而非逐个对齐
   → 函数普遍很小：中位数 40 字节，p90 227 字节，91.4% ≤256 字节，仅 267 个 >512 字节 —— 正是 AI 单次调用能完整读完并验证的粒度
   → 资产侧反而是重实现的强项：`tools/rcf.py` 已能完整解析 RCF 2.1（"ATG CORE CEMENT LIBRARY"，18,044 条目全对）、`tools/p3d.py` 能无错解析 Pure3D chunk 树（`cells.rcf` 的 520 个文件）
   → 硬依赖风险：Lua 5.1 非标准字节码（`LUA_NUMBER=float`，size_t=4）、Scaleform GFx（`GFX\x08` = SWF8 + AS2）、自研物理引擎 `ravenphysics`（281 个函数）
   → **修正结论**：路 A（重实现）是唯一能产出"杀戮尖塔式"原生应用的路线，此前低估了它
   → 另外修正一处：proto-re 那两个坏功能（Bink 视频黑屏、过场动画失效）**根本不需要 REA** —— `src/native/bink.cpp` 第 1 行注释写明「No decoder yet: BinkOpen fails, so the engine skips its movies」，17 个 Bink 函数全是空壳，而游戏里就是 Bink 1（`BIKi`）格式、FFmpeg 原生支持，补 FFmpeg 解码器 + 实现 17 个 Win32 API 即可
